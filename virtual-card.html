How MoMo → Virtual Card Works

  1. 1Create card — instant, tied to your email. Internal BIN for Phase 1; real Visa in Phase 2.
  2. 2Fund two ways: Direct (MoMo → this card) or Wallet (MoMo → wallet → any card). Same Paystack MoMo rail as your pay.html.
  3. 3Auto-convert GHS → USD at ~GH₵ 15.8/USD (configurable via VIRTUAL_CARD_FX_RATE).
  4. 4Pay: Phase 1 — at any Valmont Pay merchant (closed-loop). Phase 2 — anywhere Visa is accepted.

Ghana context — MTN already does this

MTN MoMo + Mastercard launched a virtual card in Mar 2024 for 13 African markets [incl. Ghana]. Valmont’s edge: multiple branded cards, per-card limits, wallet, API, and merchant controls — MTN is a single wallet-linked card.

What we just shipped

✅ Backend: lib/virtual-card-store.js + /api/v1/virtual-cards/* + /api/v1/wallets/* (Supabase + in-memory fallback, same pattern as mandates).

✅ MoMo rail: Funding tries Paystack MoMo charge first (real USSD prompt), falls back to instant local credit when no key — so demo works everywhere.

✅ Wallet: One GHS wallet per email, can fund any of your cards.

✅ DB: Run scripts/supabase-virtual-cards-schema.sql in Supabase to make cards durable (same as payment_links).

Next: Real Visa (Phase 2)

To make the card work on Netflix/Amazon (outside Valmont):

  1. Create account at Strowallet or Maplerad (licensed issuer).
  2. Add STROWALLET_API_KEY / MAPLERAD_SECRET to Vercel env.
  3. We wire 3 calls: create card → fund card → webhook. ~1 file change in lib/virtual-card-store.js.

Cost: $1-2 per card, 1-2% funding fee, FX interbank+1-2%. You set the markup. BoG PSP/EMI license only needed at scale (Phase 3).
